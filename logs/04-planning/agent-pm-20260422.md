### CI/CD Pipeline

**GitHub Actions Workflow** (`.github/workflows/release.yml`):

**Build Job** (on version tags):
1. Setup Node.js (v18)
2. Install dependencies (`npm ci`)
3. Run tests (unit + integration + E2E)
4. Check coverage threshold (≥80%)
5. Build backend (`tsc`)
6. Build frontend (`vite build`)
7. Package extension (`vsce package`)
8. Generate checksum (SHA256)
9. Upload artifacts (.vsix + checksum)

**Publish Job** (if build passes):
1. Download artifacts (.vsix + checksum)
2. Publish to VS Code Marketplace (`vsce publish`)
3. Create GitHub Release (attach .vsix + checksum)

**Quality Gates** (CI/CD enforced):
- ✅ All unit tests pass (Jest + Vitest)
- ✅ All integration tests pass
- ✅ All E2E tests pass (Playwright)
- ✅ Coverage ≥80%
- ✅ 0 accessibility violations (axe-core)
- ✅ Build succeeds (no TypeScript errors)

**Rollback Triggers** (automated):
- ❌ Test suite fails (any test fails)
- ❌ Coverage drops below 80%
- ❌ Build fails (TypeScript errors)

### Rollback Procedures

**Rollback Process** (<2 hour target):

**Step 1: Unpublish Current Version**
```bash
npx vsce unpublish pixel-agents --version 2.0.1
```

**Step 2: Republish Previous Stable Version**
```bash
git checkout v2.0.0
npx vsce package
npx vsce publish -p $VSCE_TOKEN
```

**Step 3: Notify Users**
- Update VS Code Marketplace listing description
- GitHub Discussions announcement
- Email to beta users (if beta channel)
- Social media update (Twitter, LinkedIn)

**Step 4: Hotfix Development**
- Create hotfix branch: `git checkout -b hotfix/v2.0.2`
- Fix critical bug
- Fast-track testing (E2E + manual QA)
- Release hotfix: `git tag v2.0.2 && git push origin v2.0.2`

**Rollback Triggers** (manual decision):
- 🔴 P1 bug discovered (affects >50% users)
- 🔴 Performance regression >20%
- 🔴 Security vulnerability discovered
- 🔴 Crash rate >1%
