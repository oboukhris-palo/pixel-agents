### Test Pyramid Structure

**Distribution** (55-70% unit, 20-30% integration, 10-15% E2E):

```
┌─────────────────────────────────────┐
│  E2E Tests (10-15%)                 │  Playwright
│  - BDD scenario execution           │  - Extension activation
│  - Complete TDD workflows           │  - Multi-project switching
│  - Milestone achievements           │  - Context window warnings
├─────────────────────────────────────┤
│  Integration Tests (20-30%)         │  Jest
│  - Monitor → Message → UI flow      │  - Message protocol contracts
│  - State synchronization            │  - File watcher → Activity detection
│  - Error propagation & recovery     │  - Backend + Frontend coordination
├─────────────────────────────────────┤
│  Unit Tests (55-70%)                │  Jest + Vitest
│  - Backend monitors (Jest 90%+)     │  - AgentActivityMonitor, ContextWindowAnalyzer

│  - Canvas logic (Phaser mocks 70%+) │  - OfficeScene, sprite animations
└─────────────────────────────────────┘
```

**Rationale**: Fast unit tests provide majority of coverage; E2E tests validate critical paths only

### Accessibility Testing Strategy

**Standard**: **WCAG 2.1 AA Compliance** (100% required)

**Tools**:
- **axe-core** — Automated accessibility scanning (integrated in CI/CD)
- **WAVE** — Manual verification
- **Lighthouse** — Accessibility audit (part of CI pipeline)
- **Screen Readers** — NVDA (Windows), VoiceOver (macOS) manual testing

**Accessibility Test Checklist**:
- ✅ Keyboard navigation (all interactive elements focusable, logical Tab order)
- ✅ Focus indicators (3px outline visible on :focus state)
- ✅ Color contrast (4.5:1 for text, 3:1 for UI elements per WCAG)
- ✅ ARIA labels (all non-text content described)
- ✅ Font sizing (zoomable to 200% without horizontal scroll)
- ✅ Alternative text (images, icons, canvas sprites described)

**Enforcement**: CI/CD blocks merge if axe-core reports >0 accessibility violations

**Example Accessibility Test** (from test-strategies.md):
```typescript
// Automated axe-core scan
await injectAxe(page);
const violations = await checkA11y(page);
expect(violations).toHaveLength(0); // Zero violations required

// Keyboard navigation test
await page.keyboard.press('Tab');
expect(focusedElement).toBe('previous-task');
await page.keyboard.press('Enter'); // Should activate
```

### CI/CD Integration

**Pipeline**: GitHub Actions (`.github/workflows/test.yml`)

**Jobs**:
1. **unit-tests** — Run Jest (backend) + Vitest (frontend), upload coverage to Codecov
2. **integration-tests** — Verify message protocol and state management
3. **e2e-tests** — Playwright tests with artifacts (screenshots, videos, traces)
4. **accessibility-tests** — axe-core scans with violation reports
5. **performance-tests** — Canvas FPS + message latency benchmarks
6. **coverage-gate** — Block merge if coverage <80%

**Pre-Commit Hooks** (Husky + lint-staged):
- Run tests for changed files only (fast feedback)
- Lint TypeScript with ESLint
- Format with Prettier
- Prevent commits if tests fail

**Quality Gate Enforcement**:
- ❌ Block merge if unit coverage <85% (backend) or <85% (frontend)
- ❌ Block merge if integration coverage <80%
- ❌ Block merge if any E2E test fails
- ❌ Block merge if accessibility violations >0
- ❌ Block merge if performance benchmarks regress

### Test Data Management Strategy

**Approach**: **Fixture-based test data** with realistic project structures

**Test Fixtures** (organized by complexity):
```
tests/fixtures/
├── minimal-project/           # 1 epic, 2 stories (for unit tests)
├── multi-epic-project/        # 3 epics, 10 stories (for integration tests)
├── large-project/             # 5 epics, 50 stories (for performance tests)
└── edge-cases/
    ├── empty-project/         # No stories (edge case handling)
    ├── malformed-yaml/        # Invalid YAML (error handling)
    └── missing-files/         # Incomplete structure (resilience tests)
```

**Test Data Factory** (Builder pattern):
```typescript
// Example from test-strategies.md
ProjectFactory.createMinimalProject(path);
ProjectFactory.createStoryWithProgress(path, 'EPIC-001', 'US-001', layer: 2, completed: true);
```

**Benefits**:
- Consistent test data across all test types
- Easy to create variations (happy path, edge cases, error scenarios)
- Realistic project structures (not mocked data)
- Fast test execution (pre-built fixtures)
